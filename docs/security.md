# Безопасность и приватность

> Набросок, не финал

Бот видит паспорта и договоры, поэтому главное правило: не хранить ни файлы, ни их текст дольше, чем нужно для обработки.

- **Хранение в Telegram.** Пока Drive не подключён, файл остаётся в Telegram (входящая папка), в БД — только `file_id` + категория + имя. `file_id` привязан к боту: доступ к файлам теряется только при удалении бота или потере Telegram-аккаунта владельца бота. Поэтому ведём к подключению Drive — надёжная копия на стороне пользователя.
- **Токен бота.** `file_id` можно скачать любым, у кого есть токен нашего бота, то есть **утёкший токен = доступ ко всем файлам всех юзеров**. Только в переменных окружения, никогда в логах и коде. При утечке — Revoke в BotFather: это выдаёт новый токен, а старые `file_id` продолжают работать у бота (не теряем доступ).
- **OAuth scope `drive.file`.** Доступ только к файлам, созданным ботом. Не требует платного аудита CASA, в отличие от полного доступа к Drive. Перепроверить по текущим правилам Google.
- **Токены Google.** `refresh_token` шифруется (AES-GCM, envelope encryption), ключ в переменных окружения Railway, не в БД. Access token только в памяти.
- **OAuth-флоу.** Одноразовый `state` с PKCE verifier в таблице `oauth_states` (TTL 10 мин), берётся и удаляется в callback. Привязка к `tg_user_id` — через запись в `oauth_states`. Иначе чужой Drive можно привязать к своему аккаунту.
- **Файлы.** По умолчанию не скачиваем — храним только `file_id`. При выгрузке на Drive файл обрабатывается в памяти и удаляется сразу после загрузки.
- **LLM (v2).** Провайдер с режимом без хранения и без обучения на данных. В БД — только тип, название и даты, без номеров документов и ИИН.
- **Логи.** Без содержимого документов, токенов и `file_id`; фильтр PII на выходе логгера.
- **Удаление.** «Удалить мои данные» стирает метаданные (включая `file_id`) и отзывает токен у Google; файлы на Drive остаются у пользователя.
- **Правовое.** Политика конфиденциальности (нужна и для верификации Google). Требования закона РК о персональных данных — открытый вопрос.
