# Безопасность и приватность

> Набросок, не финал

Бот видит паспорта и договоры, поэтому главное правило: не хранить ни файлы, ни их текст дольше, чем нужно для обработки.

- **Хранение в Telegram.** По умолчанию файл остаётся в Telegram, в БД — только `file_id` + категория + имя. Telegram не гарантирует вечное хранение; потеря токена бота или удаление бота = потеря доступа к файлам. Подключённый Drive — надёжная копия на стороне пользователя.
- **Токен бота.** `file_id` работает только с токеном нашего бота, то есть **токен бота = доступ ко всем файлам всех юзеров**. Только в переменных окружения, никогда в логах и коде. При утечке — Revoke в BotFather (инвалидирует все `file_id`).
- **OAuth scope `drive.file`.** Доступ только к файлам, созданным ботом. Не требует платного аудита CASA, в отличие от полного доступа к Drive. Перепроверить по текущим правилам Google.
- **Токены.** `refresh_token` шифруется (AES-GCM, envelope encryption), ключ в переменных окружения Railway, не в БД. Access token только в памяти.
- **OAuth-флоу.** Подписанный `state` с TTL, привязанный к `tg_user_id`, плюс PKCE. Иначе чужой Drive можно привязать к своему аккаунту.
- **Файлы.** По умолчанию не скачиваем — храним только `file_id`. При бэкапе на Drive файл обрабатывается в памяти и удаляется сразу после выгрузки.
- **LLM (v2).** Провайдер с режимом без хранения и без обучения на данных. В БД — только тип, название и даты, без номеров документов и ИИН.
- **Логи.** Без содержимого документов, токенов и `file_id`; фильтр PII на выходе логгера.
- **Удаление.** «Удалить мои данные» стирает метаданные (включая `file_id`) и отзывает токен у Google; файлы на Drive остаются у пользователя.
- **Правовое.** Политика конфиденциальности (нужна и для верификации Google). Требования закона РК о персональных данных — открытый вопрос.
